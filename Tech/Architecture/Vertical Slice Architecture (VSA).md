## Суть
Отказ от горизонтального разделения (Слой UI, Слой Логики, Слой Данных) в пользу вертикального. Весь код, относящийся к одной бизнес-функции (фиче), лежит в одной папке.
Главный принцип: **"Files that change together, stay together"** (Файлы, которые меняются вместе — лежат вместе).

## Структура
Структура плоская или сгруппированная по доменам. Внутри папки фичи лежит всё: и компоненты, и стор, и API запросы.
Один из примеров: [[VSA]]

```text
src/
  features/
    login/           # Слайс "Вход"
      LoginButton.vue
      LoginForm.vue
      useLogin.ts    (Логика + API)
    
    task-list/       # Слайс "Список задач"
      TaskItem.vue
      TaskList.vue
      tasksStore.ts
      
  shared/            # Общие утилиты (DateFormatter, Button)
```
## Плюсы
- **Низкая связность (Low Coupling):** Можно удалить папку `task-list`, и остальное приложение не заметит.
- **Скорость разработки:** Не нужно прыгать по папкам `services`, `components`, `stores`, чтобы добавить одно поле.
- **Гибкость:** Внутри папки `login` можно писать код как угодно, хоть спагетти, это не затронет другие фичи.

## Минусы
- **Дублирование кода:** Часто проще скопировать кусок логики в другую фичу, чем выносить в Shared.
- **Хаос при росте:** Без строгих правил папки фич могут разрастаться в мини-монолиты с запутанными зависимостями друг от друга.

## Когда использовать
- Быстрые MVP.
- Проекты, где фичи мало пересекаются друг с другом.
- Команды, которые не хотят учить сложные правила FSD.
