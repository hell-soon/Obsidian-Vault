##  Суть
Это **стандартизированная** и строгая реализация идей VSA. FSD не просто группирует код по фичам, но и вводит жесткую иерархию **слоев**. Импорты разрешены только **сверху вниз**. Нижний слой не может знать о верхнем.

##  Структура
Строго фиксированные слои (Layers).

```text
app/          # Инициализация (Styles, Providers)
processes/    # Сложные сценарии (Checkout, Auth flow) - deprecated в v2, но встречается
pages/        # Страницы (Роутинг)
widgets/      # Самостоятельные блоки (Header, PostList)
features/     # Пользовательские сценарии (LikePost, AddToCart)
entities/     # Бизнес-сущности (User, Post, Comment)
shared/       # Переиспользуемый код (UI Kit, API client)
```

##  Плюсы
- **Предсказуемость:** Новый разработчик точно знает, куда положить файл (сущность или фича?).
- **Контроль зависимостей:** Архитектура запрещает циклические зависимости и "спагетти" между фичами на уровне линтера.
- **Масштабируемость:** Лучший выбор для проектов, которые будут развиваться годами.

## Минусы
- **Высокий порог входа:** Нужно выучить, чем *Entity* отличается от *Feature*, а *Widget* от *Page*.
- **Boilerplate:** Нужно создавать много папок и файлов (`index.ts`, `model/`, `ui/`) даже для простых вещей.
- **Сложность рефакторинга:** Перенос кода из фичи в виджет требует изменения импортов везде.

## Когда использовать
- Enterprise-проекты.
- Крупные команды, где нужны жесткие стандарты.
- Долгоживущие приложения (Nuxt, React, Vue).
